ВВЕДЕНИЕ

Автоматизированный анализ видеопотоков с беспилотных летательных аппаратов (БПЛА) становится ключевым инструментом в задачах мониторинга дорожной обстановки, городского планирования и обеспечения безопасности. Однако реальные условия аэросъёмки характеризуются существенной вариативностью качества изображения: аппаратные шумы матрицы, агрессивное сжатие видеопотока, изменение освещённости, расфокусировка или динамическое размытие неизбежно искажают визуальные признаки объектов. Современные детекторы на основе архитектуры трансформеров (в частности, семейства DETR) демонстрируют высокую точность в контролируемых условиях благодаря механизмам глобального внимания и отказу от постобработки (NMS) [1]. Тем не менее, их устойчивость к типовым искажениям в контексте аэровидеодетекции изучена недостаточно. Количественная оценка деградации качества при различных сценариях искажений необходима для обоснованного выбора архитектур, разработки стратегий предобработки кадров и прогнозирования работоспособности систем в реальных условиях эксплуатации.

Объект научного исследования: процессы автоматической детекции и локализации транспортных средств на видеокадрах, полученных с БПЛА.

Предмет научного исследования: устойчивость архитектуры RT-DETR к синтетическим искажениям изображений, имитирующим типовые деградации аэровидеопотока.

Цель научного исследования на текущий этап: экспериментально оценить влияние различных типов искажений на качество детекции моделью RT-DETR и выявить наиболее критичные факторы, определяющие деградацию результатов.

Для достижения поставленной цели сформулированы следующие задачи:

1.  Провести анализ архитектуры DETR/RT-DETR и обосновать её применение для задачи детекции в условиях аэросъёмки.

2.  Сформировать репрезентативный эталонный набор данных из кадров аэровидеозаписей с ручной верификацией разметки.

3.  Разработать программный комплекс для автоматизированного моделирования искажений (гауссовский шум, JPEG-сжатие, изменение яркости/контраста, гауссовское размытие) и проведения серийных экспериментов.

4.  Обосновать выбор набора метрик оценки (AP@50, Recall, F1, Mean IoU, rPC), позволяющих раздельно анализировать полноту обнаружения, точность локализации и интегральную устойчивость модели.

5.  Выполнить вычислительные эксперименты, проанализировать зависимость метрик от параметров искажений и сформулировать выводы о применимости RT-DETR в реальных сценариях.

1.  Архитектура DETR

Задача детекции объектов на видеопотоке состоит в том, чтобы на каждом входном кадре определить набор объектов: их классы и координаты ограничивающих рамок. Формально задача может быть определена следующим образом.

Каждый входной кадр является изображением, который можно представить как тензор:

I ∈ ℝ^(H × W × C),

где H и W – высота и ширина изображения, C – число цветовых каналов. Результатом работы детектора является множество предсказаний

Ŷ = {ŷ₁, ŷ₂, …, ŷ_(N)},

где каждое предсказание ŷ_(j) включает класс объекта, координаты ограничивающей рамки и оценку уверенности модели [2,3].

Архитектура DETR (DEtection TRansformer), предложенная Карьоном и соавторами в 2020 году, переформулировала задачу детекции объектов как задачу прямого предсказания множества – set prediction. В отличие от классических методов, где конвейер детекции состоит из нескольких последовательных этапов с ручными эвристиками (anchor boxes, non-maximum suppression), DETR обучается как единая end-to-end система: изображение подаётся на вход, а на выходе сразу формируется финальный набор детекций без какой-либо постобработки [3].

На первом этапе входное изображение I обрабатывается опорной свёрточной нейронной сетью (backbone), например ResNet, которая извлекает карту признаков:

F = ψ(I), F ∈ ℝ^(H^(′) × W^(′) × d),

где ψ – нелинейное отображение, реализуемое свёрточной нейронной сетью, H^(′) и W^(′) — пространственные размеры карты признаков, d – размерность признакового пространства. Опорная свёртойная сеть преобразует изображение в компактное семантическое описание, пригодное для дальнейшего анализа трансформером.

Поскольку трансформер работает с последовательностями, двумерная карта признаков разворачивается в набор из L = H^(′) ⋅ W^(′) векторов. Однако при таком преобразовании теряется информация о пространственном расположении элементов, поэтому к каждому вектору добавляется позиционное кодирование:

z_(i)⁽⁰⁾ = x_(i) + p_(i), i = 1, …, L,

где x_i – вектор признаков i-й позиции на карте, p_i – соответствующий позиционный вектор. Без этого дополнения модель не могла бы различать одинаковые признаки, расположенные в разных частях кадра [4].

Полученная последовательность подаётся в encoder трансформера. Его основой является механизм самовнимания (self-attention). Для входной матрицы Z формируются матрицы запросов, ключей и значений:

Q = ZW_(Q), K = ZW_(K), V = ZW_(V),

где W_(Q), W_(K), W_(V) – обучаемые параметры. Операция внимания вычисляется по формуле:

$$Attention(Q,K,V) = softmax\left( \frac{QK^{T}}{\sqrt[\ ]{d_{k}}} \right)V.$$

Механизм глобального самовнимания позволяет модели оценивать взаимное расположение объектов в кадре, что особенно важно для аэросъёмки, где транспортные средства часто находятся в плотных группах или частично перекрывают друг друга. Иначе говоря, каждый фрагмент изображения анализируется не изолированно, а в контексте всей сцены целиком, что особенно полезно при детекции объектов в сложных условиях.

После encoder-блока запускается decoder, который работает с набором обучаемых векторов – object queries Q^(obj) = {q₁, …, q_(N)}, q_(j)∈ ℝ^(d). Каждый такой запрос соответствует одному потенциальному объекту. В процессе обучения запросы специализируются на поиске конкретных конфигураций признаков. На выходе decoder для каждого запроса формируется скрытое представление h_j, из которого предсказываются класс и координаты рамки:

p̂_(j) = softmax(W_(c)h_(j) + b_(c)),

b̂_(j) = σ(W_(b)h_(j) + b_(b)), b̂_(j) ∈ [0, 1]⁴,

где p̂_(j) – вектор вероятностей классов (включая специальный класс «нет объекта»), b̂_(j)∈ [0, 1]⁴ – нормированные параметры ограничивающей рамки в формате (c_(x), c_(y), w, h), σ – сигмоидальная функция, W_(c), W_(b), b_(c), b_(b) – обучаемые параметры.

Для обучения используется двудольное сопоставление (bipartite matching) между множеством истинных объектов Y и множеством предсказаний Ŷ. Требуется найти такую перестановку σ, которая минимизирует суммарную стоимость сопоставления:

$$\hat{\sigma} = arg\min_{\sigma \in S_{N}}\sum_{i = 1}^{N}{L_{match}\left( {y_{i},{\hat{y}}_{\sigma(i)}} \right).}$$

Это сопоставление вычисляется венгерским алгоритмом и обеспечивает взаимно-однозначное соответствие: каждому реальному объекту сопоставляется ровно один выходной слот модели. После нахождения оптимального соответствия итоговая функция потерь записывается в следующем виде:

$$L_{Hungarian}(Y,\hat{Y}) = \sum_{i = 1}^{N}{\left( {- log{\hat{p}}_{\hat{\sigma}(i)}(c_{i}) + \mathbb{I}_{\{ c_{i} \neq \varnothing\}}L_{box}\left( {b_{i},{\hat{b}}_{\hat{\sigma}(i)}} \right)} \right),}$$

где p̂_(σ̂(i))(c_(i)) – предсказанная вероятность правильного класса, 𝕀_({c_(i) ≠ ⌀}) – индикатор наличия реального объекта, L_(box) – потеря локализации рамки. Штраф за локализацию вычисляется только для реальных объектов, не для пустых слотов. Потеря локализации задаётся как взвешенная сумма L₁-потери и обобщённой IoU потери (generalized IoU loss):

L_(box)(b, b̂) = λ_(IoU)L_(IoU)(b, b̂) + λ_(L1)∥b − b̂∥₁. 

Такое объединение используется по следующей причине: компонента L₁ штрафует за абсолютное отклонение координат, а IoU-компонента отражает геометрическое совпадение областей, что лучше согласуется с реальной метрикой качества детекции. Благодаря bipartite matching модель никогда не предсказывает дублирующиеся рамки, что полностью исключает необходимость в NMS [5].

В практической части данной работы используется модель RT-DETR (Real-Time DETR), которая сохраняет описанную концепцию end-to-end детекции без NMS, но адаптирована для работы в режиме реального времени. Ключевые отличия — эффективный гибридный encoder для обработки многомасштабных признаков, механизм uncertainty-minimal query selection для формирования начальных object queries и возможность регулировать число decoder-слоёв без повторного обучения модели. Это делает RT-DETR более удобным инструментом для вычислительных экспериментов на видеоданных по сравнению с исходной архитектурой DETR.

4.  Аддитивный гауссовский шум

Тепловой шум матрицы сенсора и шум усилительных цепей камеры принято аппроксимировать аддитивным белым гауссовским шумом. Он наиболее выражен при съёмке в условиях низкой освещённости и при высоких значениях ISO. Модель искажения записывается в виде:

Ĩ(x, y) = I(x, y) + 𝒩(0, σ²),

где σ – среднеквадратическое отклонение, управляющее интенсивностью шума. Значения пикселей после добавления шума ограничиваются диапазоном [0, 255]. В экспериментах варьируется параметр σ.

Предположительно, при малых σ влияние на детекцию будет незначительным, поскольку свёртки backbone усредняют шум, из-за чего он практически не влияет на карту признаков. При высоких σ возможна деградация карты признаков, что может привести к росту числа пропущенных объектов.

5.  JPEG-сжатие

JPEG является наиболее распространённым форматом хранения и передачи изображений. При сохранении и последующем открытии кадра из видеопотока JPEG-артефакты присутствуют в большинстве пайплайнов обработки. Алгоритм основан на дискретном косинусном преобразовании (ДКП) блоков 8×8 пикселей с последующим квантованием коэффициентов. ДКП для блока 8×8 представлена на формуле 11. Степень потерь определяется коэффициентом качества Q – коэффициент масштабирования матрицы квантования; Q ∈ [1, 100]: при малых Q агрессивно удаляются высокочастотные компоненты, что порождает характерные блочные артефакты на границах блоков.

$$F(u,v) = \frac{1}{4}C(u)C(v)\sum_{x = 0}^{7}{\sum_{y = 0}^{7}{I(x,y)\cos\left( \frac{(2x + 1)u\pi}{16} \right)\cos\left( \frac{(2y + 1)v\pi}{16} \right)}},$$

где u, v – индексы частотных компонент, $C(0) = \frac{1}{\sqrt{2}},\ C(k) = 1$ при k > 0.

Предположительно, при низком Q потеря высокочастотных деталей (рёбра, текстуры) снизит качество локализации объектов. Особенно сильный эффект ожидается для небольших объектов, чьи признаки занимают мало пикселей.

6.  Изменение яркости и контраста

Вариации условий освещения (пересвет, недоэкспонирование, затемнённые зоны) принято аппроксимировать линейным преобразованием пикселей:

Ĩ(x, y) = α ⋅ I(x, y) + β,

где α – коэффициент масштабирования (контраст), β – смещение яркости. При α < 1 контраст снижается (сужение гистограммы), при β< 0 изображение темнеет. В экспериментах варьируется диапазон яркостной гистограммы через совместное изменение α и β при фиксированном среднем значении яркости, а также отдельно – только β.

Предположительно, сужение диапазона яркости приведёт к уменьшению чёткости контуров объектов из-за уменьшения перепада значений граничных пикселей, что отразится на точности границ ограничивающих рамок.

7.  Гауссовское размытие

Расфокусировка объектива и движение камеры или объекта приводят к размытию кадра. Изотропная дефокусировка хорошо аппроксимируется гауссовым фильтром: кадр свёртывается с двумерным гауссовым ядром G_(σ), параметр которого σ определяет радиус размытия. В экспериментах варьируется σ ядра свёртки. Ядро гауссова фильтра имеет определяется формулой:

$$G_{\sigma}(x,y) = \frac{1}{2\pi\sigma^{2}}\exp\left( {- \frac{x^{2} + y^{2}}{2\sigma^{2}}} \right).$$

Поскольку гауссовый фильтр является низкочастотным, он подавляет высокочастотные градиенты, от которых зависит обнаружение рёбер в backbone. Предположительно, при достаточно большом σ контуры объектов сольются с фоном, что снизит точность локализации и приведёт к пропускам.

8.  Метрики качества детекции

По результатам работы RT-DETR на видеозаписях для каждого кадра формируется набор предсказанных ограничивающих рамок с координатами, классом объекта и уверенностью модели в диапазоне от 0 до 1. Для каждого кадра также присутствует набор эталонных (размеченных человеком) объектов и их рамок. Необходимо выбрать, как именно предсказания модели будут сопоставляться с эталоном и переводиться в числовые характеристики потерь [6,7,8].

Несмотря на то, что при обучении RT-DETR используется Hungarian loss, для оценки результатов её обычно не применяют, так как выходное значение потерь сложно интерпретировать. Данная величина не отражает напрямую количество пропущенных объектов или точность локализации. Поэтому в рамках экспериментальной оценки качества на тестовых данных применяются стандартные внешние метрики детекции: AP, Recall, F1, general IoU и rPC.

Предсказание считается верным (True Positive, TP), если одновременно выполнены два условия:

1.  Предсказанный класс совпадает с эталонным.

2.  IoU между предсказанной рамкой и ближайшей эталонной рамкой не ниже заранее выбранного порогового значения τ (например, 0,5).

Предсказание, не удовлетворяющее этому условию, считается ложным срабатыванием (False Positive, FP). Эталонный объект, не покрытый ни одной предсказанной рамкой с нужным IoU, считается пропущенным (False Negative, FN).

$${IoU}(b_{pred},\ b_{gt}) = \frac{|b_{pred} \cap b_{gt}|}{|b_{pred} \cup b_{gt}|},$$

где b_(pred) – предсказанная рамка, b_(gt) – эталонная рамка, числитель – площадь пересечения рамок, знаменатель – площадь их объединения.

AP (Average Precision) – площадь под кривой Precision–Recall, построенной по всем порогам уверенности модели. Это позволяет оценить качество детектора независимо от конкретного выбранного порога уверенности. Наиболее популярным порогом является IoU = 0,5, что соответствует стандарту PASCAL VOC. Вычислить AP можно по формуле:

$${AP} = \sum_{n}^{\ }{\ \left( R_{n} - R_{n - 1} \right) \cdot P_{n},}$$

где P_(n) и R_(n) – значения точности (Precision) и полноты (Recall) соответственно при n-м пороге уверенности, упорядоченных по убыванию.

AP@50 – основная метрика для сравнения работы модели на чистых и искажённых данных. Она учитывает одновременно и точность, и полноту при всех возможных рабочих точках, поэтому лучше отражает общее качество, чем точечные метрики при фиксированном пороге. Недостаток: менее чувствительна к ошибкам локализации, чем AP@75 или AP@50:95, так как засчитывает как верные все рамки с перекрытием более 50%.

F1-score – гармоническое среднее точности (Precision) и полноты (Recall) при фиксированном пороге уверенности. Преимущество F1 – возможность отслеживать изменения качества одним числом и строить зависимость F₁(λ), где λ – параметр искажения. Если один из компонентов (Precision или Recall) резко падает, F1 немедленно это отражает. В работе порог уверенности фиксируется на значении, найденном по результатам работы модели на чистых данных как оптимальная рабочая точка кривой Precision-Recall [9].

Recall и F1 фиксируют факт обнаружения объекта, но не говорят, насколько точно определены границы рамок. Среднее IoU (general IoU) по всем верно обнаруженным объектам позволяет отдельно отследить деградацию локализации:

$$\overline{IoU} = \frac{1}{|{TP}|}\sum_{i\  \in \ {TP}}^{\ }{{IoU}(b_{pred}^{i},\ b_{gt}^{i})}.$$

Эта метрика актуальна прежде всего для размытия и JPEG-сжатия: контуры объектов становятся менее чёткими, и рамки предсказываются с меньшей точностью даже при том, что объект по-прежнему обнаруживается. Падение среднего IoU без падения Recall – характерный признак деградации локализации при сохранении способности к обнаружению [7].

Относительное качество при искажениях. Для обобщённой оценки устойчивости модели используется метрика rPC (relative Performance under Corruption), предложенная в работе [Michaelis et al., 2019]. Сначала вычисляется mPC – среднее значение выбранной метрики (AP@50) по всем типам искажений и всем уровням интенсивности:

$${mPC} = \frac{1}{N_{c}}\sum_{c = 1}^{N_{c}}{\frac{1}{N_{s}}\sum_{s = 1}^{N_{s}}P_{c,s}},$$

где P_(c, s) – значение AP@50 для типа искажения c при уровне интенсивности s; N_(c) – число типов искажений; N_(s) – число уровней интенсивности для каждого типа [10, 11].

Далее mPC нормируется на значение метрики на чистых данных:

$${rPC} = \frac{mPC}{P_{clean}},$$

где P_(clean) – AP@50 на чистых кадрах. rPC ∈ [0, 1]: значение 1 означает, что искажения не влияют на качество модели; значение 0,7 – что в среднем по всем искажениям модель сохраняет 70% своего качества на чистых данных. rPC позволяет охарактеризовать устойчивость модели одним числом, обобщив результаты всех экспериментов.

9.  Программная реализация и подготовка данных

В качестве основного языка разработки программного комплекса выбран Python. Выбор обусловлен его де-факто статусом стандарта в области машинного обучения и компьютерного зрения: большинство актуальных библиотек для работы с нейронными сетями и обработки изображений имеют именно Python-интерфейс.

Для выполнения инференса и работы с моделью RT-DETR использована библиотека Ultralytics [12,13], для обработки изображений — OpenCV [14], для расчёта метрик и формирования таблиц — NumPy [15] и Pandas, для построения графиков — Matplotlib и Seaborn. Параметры эксперимента вынесены в отдельный конфигурационный файл config.yaml, что позволяет воспроизводить серии запусков без изменения исходного кода.

Программный комплекс организован в виде трёх последовательно выполняемых скриптов: подготовка и разметка эталонного набора кадров, проведение серии экспериментов с искажениями и последующий расчёт метрик качества. Такое разделение позволяет независимо выполнять инференс и анализ результатов. Разметить датасет можно только один раз, а после получения файла с предсказаниями метрики можно пересчитывать повторно без нового запуска модели.

10. Формирование эталонного набора данных

Исходные данные представляют собой кадры аэровидеосъёмки с беспилотного летательного аппарата. Для эксперимента используются видеофрагменты, из которых программа берёт заданное число кадров с указанным шагом между кадрами. Такой способ отбора нужен для того, чтобы соседние изображения не дублировали друг друга почти полностью и итоговая выборка содержала более разнообразные сцены из одного видеофайла.

Разметка датасета выполняется в полуавтоматическом режиме. Сначала модель RT-DETR строит предварительные ограничивающие рамки, после чего в небольшом графическом интерфейсе вручную проверяются и исправляются рамки. В результате формируется json-файл, содержащий список объектов для каждого кадра; этот файл далее используется как единая эталонная разметка для расчёта метрик.

При частичном перекрытии объекта рамка строится по видимой части транспортного средства. Полностью скрытые области не дорисовываются. Если отдельные небольшие выступающие детали приводят к сильному увеличению фона в рамке, они могут не включаться. Такой способ разметки соответствует обычной постановке задачи двумерной детекции и уменьшает разброс в ручных аннотациях.

11. Подготовка к проведению серии экспериментов

Основная логика экспериментов реализована в скрипте run_experiments. Для каждой экспериментальной серии программа считывает исходные кадры, применяет к ним выбранное искажение, запускает RT-DETR и сохраняет полученные предсказания в файл json-файл. Отдельно выполняется серия clean, в которой кадры подаются на вход модели без дополнительных преобразований; она используется как базовая линия при сравнении результатов.

В конфигурации эксперимента предусмотрено пять семейств серий: гауссовский шум, JPEG-сжатие, гауссовское размытие, изменение яркости и изменение контраста. Для каждого семейства задан набор уровней, определяющих силу искажения. Яркость и контраст реализуются через общее линейное преобразование пикселей, однако в эксперименте и при последующем анализе будут рассматриваться как два разных вида деградации изображения.

Для гауссовского шума варьируется параметр sigma, для JPEG-сжатия — коэффициент качества quality, для размытия — параметр sigma и размер ядра ksize, для яркости — параметр beta, для контраста — параметр alpha. Все серии задаются через config.yaml, поэтому изменение числа уровней или диапазона искажений не требует переписывания основной логики сценария.

Эксперимент проводится не на одном изолированном наборе кадров, а на объединённом наборе из нескольких размеченных датасетов. В конфигурации перечисляются все папки, которые должны войти в общий запуск. При формировании объединённого эксперимента имена кадров логически префиксируются именем исходного датасета, что исключает коллизии файлов при совпадении названий кадров в разных папках. Такое объединение делает итоговые оценки менее зависимыми от особенностей одного конкретного видео. Метрики рассчитываются сразу по совокупности сцен с разной плотностью объектов и разной структурой дорожной обстановки. Это особенно важно в задаче аэровидеодетекции, где отдельные фрагменты съёмки могут заметно различаться по сложности.

12. Расчёт метрик и представление результатов

Расчёт итоговых показателей выполняется на основе записанных json-файлов с эталонной разметкой и предсказанными результатами. Для каждой экспериментальной серии все предсказания объединяются по кадрам, после чего сопоставляются с эталонной разметкой по двум условиям: совпадение класса объекта и значение IoU не ниже порога 0,5. Если для предсказания находится подходящий несопоставленный эталонный объект, оно считается истинно положительным; в противном случае — ложным срабатыванием.

Перед сопоставлением предсказания сортируются по убыванию уверенности модели. На этой основе строится зависимость precision–recall и вычисляется метрика AP@50. Дополнительно для каждой серии рассчитываются Recall, F1 и средний IoU по всем корректно сопоставленным объектам. Такой набор метрик позволяет отдельно анализировать общее качество детекции, полноту обнаружения и точность локализации рамок.

Итоговый результат записывается в csv-файл в виде таблицы со значениями всех метрик по всем сериям. Для визуального анализа автоматически строятся графики AP@50, Recall, F1 и Mean IoU для каждого семейства серий, а также столбчатая диаграмма среднего значения relative_AP по типам искажений. Такой набор рисунков позволяет сначала сравнить общую устойчивость модели к различным видам деградации, а затем отдельно рассмотреть, как изменяются полнота обнаружения и точность локализации.

По мере роста интенсивности искажения все четыре метрики снижаются, однако скорость деградации у них различается: наиболее заметно уменьшаются AP@50 и Recall, тогда как Mean IoU падает более плавно.

Такой характер деградации объясняется тем, что шум разрушает мелкие текстурные детали и делает границы небольших транспортных средств менее различимыми на фоне дорожного полотна. Для аэровидеосъёмки это особенно критично, поскольку значительная часть объектов занимает небольшую площадь кадра. На практике это означает, что в условиях сильной зернистости модель начинает чаще пропускать объекты, прежде всего небольшие и удалённые.

17. JPEG-сжатие

JPEG-сжатие моделирует потери качества, связанные с компрессией видеопотока и появлением блочных артефактов. В данном случае интерес представляет не только общее падение качества, но и то, насколько долго модель сохраняет устойчивость при постепенном уменьшении качества кодирования.

В эксперименте использовались следующие значения параметра quality: 95, 80, 60, 40, 25, 15, 10, 7, 4, 2.

На рисунке 3 показаны зависимости AP@50, Recall, F1 и Mean IoU от коэффициента quality. При умеренном сжатии кривые изменяются сравнительно плавно, однако на низких значениях quality падение качества становится существенно более резким.

При уменьшении quality от 95 до 2 значение AP@50 снижается с 0,6701 до 0,3462, Recall – с 0,8915 до 0,6880, F1 – с 0,2872 до 0,2061, а Mean IoU – с 0,8137 до 0,6976. Следовательно, модель достаточно спокойно переносит умеренную компрессию, но при экстремальном сжатии начинает терять как полноту обнаружения, так и точность локализации.

Вероятной причиной является то, что JPEG дольше сохраняет крупные контуры и общую структуру сцены, чем, например, шум или размытие. Однако при очень низком качестве изображения начинают доминировать блочные артефакты и искажения границ объектов, что особенно мешает детекции небольших автомобилей и близко расположенных транспортных средств.

18. Гауссовское размытие

Гауссовское размытие моделирует потерю резкости, которая может быть связана с расфокусировкой, смещением камеры или motion blur. Для задачи аэровидеодетекции этот тип искажения особенно важен, так как модель в значительной степени опирается на наличие чётких контуров и локальных деталей.

В эксперименте использовались следующие значения параметра sigma: 0,5, 1, 1,5, 2,5, 3,5, 5, 7, 10, 14, 20.

На рисунке 4 приведены зависимости AP@50, Recall, F1 и Mean IoU от параметра sigma для гауссовского размытия. По всем графикам видно, что именно этот тип искажения приводит к наиболее быстрому и глубокому падению качества среди рассмотренных факторов.

При увеличении sigma от 0,5 до 20,0 значение AP@50 уменьшается с 0,6625 до 0,0498, Recall — с 0,8858 до 0,2466, F1 — с 0,2880 до 0,1232, а Mean IoU — с 0,8133 до 0,6054. Уже на средних уровнях размытия наблюдается выраженное ухудшение детекции, а при максимальных значениях параметра качество становится крайне низким.

Основная причина состоит в том, что размытие уничтожает высокочастотные признаки, по которым модель отличает транспортные средства от фона и отделяет соседние объекты друг от друга. В результате страдает не только полнота обнаружения, но и точность позиционирования рамок. Практически это означает, что потеря резкости является одним из наиболее опасных факторов для RT-DETR в рассматриваемой задаче.

19. Изменение яркости

Изменение яркости моделирует глобальное затемнение или пересвет изображения при фиксированном контрасте. Этот сценарий соответствует изменениям уровня освещённости, которые часто встречаются при съёмке с воздуха в разное время суток или при изменении погодных условий.

В эксперименте использовались следующие значения параметра beta: -80, -60, -40, -20, 0, 20, 40, 60, 80, 100.

На рисунке 5 представлены зависимости AP@50, Recall, F1 и Mean IoU от параметра beta. В отличие от шума, сжатия и размытия, во всём исследуемом диапазоне кривые меняются сравнительно слабо, а основные метрики остаются близкими к базовому уровню.

Значение AP@50 изменяется в пределах от 0,6123 до 0,6704, Recall — от 0,8619 до 0,8937, F1 — от 0,2696 до 0,2889, Mean IoU — от 0,7785 до 0,8165. Это показывает, что в исследуемом диапазоне RT-DETR сравнительно хорошо переносит глобальный сдвиг яркости.

Такой результат можно объяснить тем, что изменение яркости не разрушает пространственную структуру сцены и не искажает форму объектов. Пока контуры транспортных средств остаются различимыми, модель сохраняет способность их обнаруживать. Следовательно, само по себе изменение уровня освещённости оказывается менее опасным фактором, чем потеря резкости или появление сильных артефактов.

20. Изменение контраста

Изменение контраста моделирует сжатие или растяжение динамического диапазона изображения при фиксированном сдвиге яркости. Такой тип искажения важен тем, что он влияет не только на общую визуальную выразительность сцены, но и на различимость границ объектов.

В эксперименте использовались следующие значения параметра alpha: 0,1, 0,2, 0,4, 0,6, 1, 1,5, 2, 2,5, 3,5, 5.

На рисунке 6 показаны зависимости AP@50, Recall, F1 и Mean IoU от параметра alpha. Графики демонстрируют, что зависимость носит немонотонный и асимметричный характер: вблизи базового значения качество остаётся высоким, тогда как при экстремальных изменениях контраста начинается выраженная деградация.

При сильном снижении контраста до alpha = 0,1 значение AP@50 составляет 0,5894, а при экстремальном увеличении контраста до alpha = 5,0 оно снижается до 0,2645. Аналогично Recall уменьшается до 0,5309, F1 — до 0,1573, а Mean IoU — до 0,6719. Следовательно, сильное усиление контраста в рассматриваемом диапазоне оказывается для модели опаснее, чем его умеренное уменьшение.

Вероятная причина состоит в том, что при высоком контрасте часть локальных областей насыщается, мелкие детали теряются, а переходы становятся слишком жёсткими. При низком контрасте, напротив, границы объектов размываются визуально, однако структура сцены всё же сохраняется лучше, чем в случае пересвета и насыщения. На практике это означает необходимость контроля контрастности изображения перед подачей кадров в модель.

21. Обобщение результатов эксперимента

Проведённый эксперимент показал, что устойчивость RT-DETR к искажениям изображения существенно зависит от их физической природы. Наиболее сильное отрицательное влияние на качество детекции оказывает гауссовское размытие: при увеличении параметра σ от 0,5 до 20,0 значение AP@50 снижается с 0,6625 до 0,0498, Recall – с 0,8858 до 0,2466, а Mean IoU – с 0,8133 до 0,6054. Это означает, что потеря резкости разрушает как саму способность модели находить объекты, так и точность определения их границ, причём деградация начинается уже на средних уровнях размытия. Среди остальных факторов заметное ухудшение качества вызывают сильный гауссовский шум и экстремальное JPEG-сжатие: в этих случаях AP@50 падает соответственно до 0,2616 и 0,3462, что свидетельствует о существенном снижении качества детекции при разрушении мелких деталей изображения.

Отдельно следует отметить различие между влиянием искажений на обнаружение объектов и на точность их локализации. Для шума и JPEG-сжатия падение AP@50 и Recall происходит быстрее, чем падение Mean IoU, то есть модель в первую очередь начинает пропускать объекты, тогда как для уже обнаруженных объектов точность рамок ухудшается более плавно. Это особенно хорошо видно на крайних уровнях: при гауссовском шуме σ = 110 значение Recall снижается до 0,5662, тогда как Mean IoU остаётся на уровне 0,6810; при JPEG-сжатии с quality = 2 Recall составляет 0,6880, а Mean IoU – 0,6976. Следовательно, в этих сценариях основная проблема связана не столько с геометрией рамок, сколько с ростом числа пропущенных детекций.

Изменение контраста продемонстрировало асимметричное влияние на результат детекции. В области умеренных значений параметра α, близких к единице, качество модели остаётся высоким, однако при сильном увеличении контраста начинается выраженная деградация: при α=5,0 AP@50 уменьшается до 0,2645, Recall – до 0,5309, F1 – до 0,1573, а Mean IoU – до 0,6719. Это позволяет сделать вывод, что чрезмерное усиление контраста опаснее для RT-DETR, чем его умеренное уменьшение, поскольку приводит к насыщению локальных областей изображения и потере полезных деталей на границах объектов.

Наименее чувствительной модель оказалась к глобальному изменению яркости. Во всём исследованном диапазоне параметра β значение AP@50 изменяется только от 0,6123 до 0,6704, Recall – от 0,8619 до 0,8937, а Mean IoU – от 0,7785 до 0,8165. Это показывает, что при сохранении общей пространственной структуры сцены и различимости контуров транспортных средств RT-DETR сравнительно хорошо переносит как затемнение, так и умеренный пересвет. Таким образом, наиболее опасными для рассматриваемой задачи являются не глобальные фотометрические преобразования, а искажения, разрушающие высокочастотные признаки, границы объектов и локальную структуру изображения.

На рисунке 7 изображена столбчатая диаграмма среднего значения relative_AP по типам искажений. Согласно диаграмме, модель демонстрирует наибольшую устойчивость к изменению яркости, а также сохраняет работоспособность при умеренном JPEG-сжатии. Наиболее проблемным оказалось гауссово размытие.

Заключение

В ходе выполнения научно-исследовательской работы установлены количественные закономерности деградации качества детекции RT-DETR под воздействием пяти типов синтетических искажений в контексте аэросъёмки транспортных средств. Показано, что устойчивость модели существенно зависит от физической природы искажения: наиболее критичным фактором является гауссовское размытие (снижение AP@50 до ~0,05 при σ=20), тогда как глобальное изменение яркости в исследованном диапазоне практически не влияет на работоспособность детектора.

Выявлено асимметричное влияние искажений на этапы детекции. Экспериментально доказано, что аддитивный шум и JPEG-сжатие в первую очередь снижают полноту обнаружения (Recall), приводя к росту числа пропущенных объектов, в то время как точность локализации уже найденных объектов (Mean IoU) сохраняется на относительно высоком уровне. Это указывает на то, что данные искажения преимущественно маскируют слабо выраженные признаки, а не искажают геометрию объектов.

Подтверждена эффективность метрики rPC для интегральной оценки устойчивости детекторов. Нормирование среднего качества по всем типам и уровням искажений на базовое значение позволило свести многомерные экспериментальные данные к единому показателю, удобному для сравнения архитектур в будущих исследованиях.

Разработан и апробирован воспроизводимый программный комплекс автоматизации экспериментов, включающий модули полуавтоматической разметки, пакетного применения искажений, инференса модели и агрегированного расчёта метрик. Архитектура комплекса обеспечивает корректное объединение данных из нескольких видеопотоков и исключает зависимость оценок от особенностей отдельных сцен.

Код скрипта make_annotation

import cv2, json, shutil, yaml
import numpy as np
from pathlib import Path
from ultralytics import RTDETR
with open("config.yaml", "r", encoding="utf-8") as f:
CFG = yaml.safe_load(f)
DS_DIR = Path(CFG["dataset"]["base_dir"]) / CFG["dataset"]["name"]
FRAMES_DIR = DS_DIR / "frames"
GT_PATH = DS_DIR / "ground_truth.json"
CLASSES = CFG["annotation"]["classes"]
CLASS_COLORS = {"car": (0, 255, 0), "truck": (255, 0, 0), "bus": (0, 165, 255)}
HOVER_COLOR = (255, 255, 0)
DRAW_COLOR = (255, 0, 255)
def get_images(d, step, count):
p = Path(d)
if not p.is_dir(): raise FileNotFoundError(f"❌ Нет папки: {d}")
exts = {".jpg", ".jpeg", ".png", ".bmp"}
imgs = sorted([f for f in p.iterdir() if f.suffix.lower() in exts])
return imgs[::step][:count] or []
class Annotator:
def __init__(self, img_path, boxes, min_sz=20):
self.img = cv2.imread(str(img_path))
if self.img is None: raise ValueError(f"❌ Битый файл: {img_path}")
self.img_path, self.min_sz = img_path, min_sz
self.boxes = [b.copy() for b in boxes]
self.hovered, self.drawing = None, False
self.start, self.curr, self.has_moved = None, None, False
self.next_cls = CLASSES[0]
cv2.namedWindow("Annotator", cv2.WINDOW_NORMAL)
cv2.setMouseCallback("Annotator", self._mouse)
def _in_box(self, x, y, b):
x1, y1, x2, y2 = map(int, b['bbox'])
return x1 <= x <= x2 and y1 <= y <= y2
def _update_hover(self, x, y):
self.hovered = None
for i in range(len(self.boxes) - 1, -1, -1):
if self._in_box(x, y, self.boxes[i]):
self.hovered = i; break
def _mouse(self, e, x, y, f, p):
if e == cv2.EVENT_LBUTTONDOWN:
if self.hovered is not None:
self.boxes.pop(self.hovered)
self.hovered = None
else:
self.drawing = True
self.start = self.curr = (x, y)
self.has_moved = False
elif e == cv2.EVENT_MOUSEMOVE:
if self.drawing:
self.curr = (x, y)
if self.start != self.curr: self.has_moved = True
else:
self._update_hover(x, y)
elif e == cv2.EVENT_LBUTTONUP:
if self.drawing and self.has_moved:
x1, y1 = min(self.start[0], self.curr[0]), min(self.start[1], self.curr[1])
x2, y2 = max(self.start[0], self.curr[0]), max(self.start[1], self.curr[1])
if x2 - x1 >= self.min_sz and y2 - y1 >= self.min_sz:
self.boxes.append({"class": self.next_cls, "bbox": [int(x1), int(y1), int(x2), int(y2)],
"confidence": 1.0, "source": "manual"})
self.drawing = False
self.has_moved = False
def _draw(self, img):
out = img.copy()
for i, b in enumerate(self.boxes):
x1, y1, x2, y2 = map(int, b['bbox'])
cls = b['class']
col = HOVER_COLOR if i == self.hovered else (CLASS_COLORS.get(cls, (0,0,255)) if b.get('source')=='model' else (0,0,255))
th = 4 if i == self.hovered else 2
cv2.rectangle(out, (x1, y1), (x2, y2), col, th)
lbl = f"{cls} {b['confidence']:.2f}" if b.get('source')=='model' else cls
cv2.putText(out, f"{lbl} ({b.get('source', 'manual')})", (x1, y1 - 10),
cv2.FONT_HERSHEY_SIMPLEX, 0.5, col, 2)
if self.drawing and self.start and self.curr:
cv2.rectangle(out, self.start, self.curr, DRAW_COLOR, 2)
h, w = out.shape[:2]
cv2.putText(out, f"Файл: {self.img_path.name} | Боксов: {len(self.boxes)}",
(10, h - 20), cv2.FONT_HERSHEY_SIMPLEX, 0.6, (255, 255, 255), 2)
cv2.putText(out, f"След. класс: [{self.next_cls}] | [ЛКМ] Рис/Уд | [C] Смена | [1-3] Выбор | [SPACE] Далее | [Q] Выход",
(10, h - 40), cv2.FONT_HERSHEY_SIMPLEX, 0.5, (200, 200, 200), 1)
return out
def run(self):
while True:
if cv2.getWindowProperty("Annotator", cv2.WND_PROP_VISIBLE) < 1: return "exit"
cv2.imshow("Annotator", self._draw(self.img))
k = cv2.waitKey(10) & 0xFF
if k == 32: return "next"
if k in (ord('q'), 27): return "exit"
if k == ord('c') and self.hovered is not None:
idx = CLASSES.index(self.boxes[self.hovered]['class'])
self.boxes[self.hovered]['class'] = CLASSES[(idx + 1) % len(CLASSES)]
if k in (ord('1'), ord('2'), ord('3')):
self.next_cls = CLASSES[k - ord('1')]
return "next"
def result(self):
return {"filename": self.img_path.name, "width": self.img.shape[1],
"height": self.img.shape[0], "objects": self.boxes}
def close(self):
cv2.destroyWindow("Annotator")
def predict_transport(model, path, conf):
res = model.predict(str(path), conf=conf, verbose=False, save=False, show=False)
if not res or not res[0].boxes: return []
TARGETS = set(CLASSES)
out = []
for b in res[0].boxes:
name = res[0].names.get(int(b.cls[0]), "").lower()
if name in TARGETS:
out.append({"class": name, "bbox": b.xyxy[0].cpu().numpy().astype(int).tolist(),
"confidence": float(b.conf[0]), "source": "model"})
return out

def apply_degradation(img, deg_type, params):
img = img.copy()
if deg_type == "none": return img
if deg_type == "gaussian_noise":
sigma = params.get("sigma", 10)
noise = np.random.normal(0, sigma, img.shape)
return np.clip(img.astype(np.float64) + noise, 0, 255).astype(np.uint8)
if deg_type == "gaussian_blur":
k = params.get("ksize", 5)
sigma = params.get("sigma", 0) # ← считываем sigma из конфига
if k % 2 == 0: k += 1
return cv2.GaussianBlur(img, (k, k), sigmaX=sigma, sigmaY=sigma) # ← передаём явно
if deg_type == "jpeg_compress":
q = params.get("quality", 50)
_, enc = cv2.imencode('.jpg', img, [cv2.IMWRITE_JPEG_QUALITY, q])
return cv2.imdecode(enc, cv2.IMREAD_COLOR)
if deg_type == "brightness_contrast":
return cv2.convertScaleAbs(img, alpha=params.get("alpha", 1.0), beta=params.get("beta", 0))
return img
def draw_predictions(img, preds, classes):
out = img.copy()
for p in preds:
if p["class"] not in set(classes): continue
x1, y1, x2, y2 = map(int, p["bbox"])
cv2.rectangle(out, (x1, y1), (x2, y2), (0, 255, 0), 2)
cv2.putText(out, f"{p['class']} {p['confidence']:.2f}", (x1, y1 - 10),
cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 255, 0), 2)
return out
